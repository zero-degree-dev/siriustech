# СириусТех

Учебный сайт ИТ-компании: каталог из 12 услуг, консультация, демонстрационные кейсы и форма заявки. Главная страница работает с NestJS и PostgreSQL. Консультант получает сведения через собственный MCP-сервер и может формировать ответы через Polza AI.

## Стек

- Интерфейс: Next.js 16.4, React 19, TypeScript strict, App Router.
- Организация: Feature-Sliced Design, CSS Modules и БЭМ, общие CSS-токены.
- Графика: SVG, HTML/CSS-композиции интерфейсов, Three.js для глобуса.
- Сервер: NestJS 11, PostgreSQL 17, `pg`, Zod.
- Консультация: TypeScript MCP SDK и API Polza AI; предусмотрен справочный режим без модели.
- Проверки: Vitest, Testing Library, Playwright, ESLint, Stylelint.

Версии зависимостей и команды находятся в [package.json](package.json) и [backend/package.json](backend/package.json). Менеджер пакетов — Bun 1.4.2, зависимости фиксируются в `bun.lock`. Для запуска серверных скриптов нужен Node.js; локальная проверка выполнена на Node.js 24.

## Быстрый запуск

Все команды выполняются из корня проекта — папки с этим README.

```sh
bun install --frozen-lockfile
```

Создайте конфигурацию из примеров, сохранив уже настроенные файлы. Для PowerShell:

```powershell
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
if (!(Test-Path backend/.env)) { Copy-Item backend/.env.example backend/.env }
```

В примере установлен `CHAT_MODE=catalog`: консультант отвечает по каталогу без внешней модели. Для Polza AI задайте в `backend/.env` `CHAT_MODE=polza` и `POLZA_API_KEY`. Ключи остаются на сервере. Подробности — в [документации backend](docs/backend.md).

```sh
bun run dev
```

Команда проверяет базу, при необходимости запускает локальный PostgreSQL, собирает backend, применяет миграции и начальные данные, запускает NestJS и Next.js. Уже работающие сервисы используются повторно. Автоматический запуск базы рассчитан на стандартное локальное подключение из примера; для другого `DATABASE_URL` базу нужно запустить самостоятельно.

| Адрес | Назначение |
| --- | --- |
| http://localhost:3000 | Основной сайт |
| http://localhost:3000/ui-kit | Витрина компонентов с демонстрационными адаптерами |
| http://127.0.0.1:4000/api/health | Проверка backend и базы |
| http://127.0.0.1:4000/mcp | MCP Streamable HTTP; требует отдельного токена и MCP-клиента |

`bun run dev:services` запускает только базу и API, `bun run dev:web` — только Next.js. `docker compose up -d postgres` — альтернативный способ запустить базу. Текущий Compose содержит только PostgreSQL; весь сайт в Docker он не собирает. Не запускайте две базы на одном порту.

## Как устроено приложение

```text
app/                   маршруты, layout, favicon, серверный /api-прокси
src/app/               сборка приложения, подключение API, шрифты, глобальные стили
src/pages/             композиция главной страницы и UI kit
src/widgets/           шапка, каталог, первый экран, кейсы, глобус, этапы работы
src/features/          форма заявки и чат: UI, модели, HTTP/mock-адаптеры
src/entities/          услуга и показатели кейса
src/shared/            общие UI-компоненты, транспорт, конфигурация, токены
backend/src/           NestJS: API, каталог, консультация, MCP, база данных
backend/data/          исходный каталог для seed и демовитрины
scripts/               совместный запуск и локальный PostgreSQL
tests/                 модульные и браузерные тесты интерфейса
backend/tests/         интеграционные тесты API, базы и MCP
docs/                  документация и исходные изображения макета
pages/README.md        служебный файл для совместимости FSD с Next.js
```

Главная точка маршрута — [app/page.tsx](app/page.tsx). [LandingApp](src/app/landing-app.tsx) подключает каталог, чат и форму к API, а [HomePage](src/pages/home/home-page.tsx) задаёт порядок разделов. Браузер обращается к Next.js `/api/*`, который передаёт разрешённые запросы NestJS. MCP подключён к backend; браузер напрямую его не вызывает.

Импорт между FSD-слоями идёт сверху вниз через публичные `index.ts`. Правила проверяет ESLint. Не удаляйте `pages/README.md`: он предотвращает распознавание FSD-папки `src/pages` как Pages Router.

## Проверки

```sh
bun run typecheck
bun run lint
bun run test
bun run test:backend
bun run build
```

Сборка Next.js и сборка NestJS раздельные: для backend есть `bun run backend:build`. `bun run start` запускает только собранный Next.js; работающие API и база нужны отдельно.

Для актуальных сценариев каталога и консультации:

```sh
bunx playwright install chromium
bun run test:e2e tests/e2e/catalog.spec.ts tests/e2e/consultation.spec.ts
```

Playwright проверяет размеры 1280×900, 768×1024 и 375×812. Конфигурация запускает тестовый Next.js на порту 3001. Перед запуском остановите другой `next dev` из этой же папки: два dev-сервера используют один каталог сборки. Вместо скачанного Chromium можно выбрать установленный Edge: `$env:PLAYWRIGHT_CHANNEL='msedge'` в PowerShell.

Полный набор запускается командой `bun run test:e2e`. Старые `hero.spec.ts` и `portfolio.spec.ts` содержат ожидания от прежних анимаций и требуют актуализации; успешный запуск двух сценариев выше не означает прохождения всего набора. UI kit проверяется отдельно файлом `ui-kit.spec.ts`.

## Что показать на защите

1. Раскрыть 12 услуг и свернуть каталог: кнопка остаётся на той же высоте экрана.
2. Выбрать услугу: тема передаётся в консультацию и форму заявки.
3. Показать чат в выбранном режиме, историю и обработку ошибки с повторной отправкой.
4. Переключить демонстрационные кейсы, повернуть и остановить глобус.
5. Показать мобильное меню, форму и `/ui-kit` со состояниями компонентов.
6. Объяснить цепочку «интерфейс → API → MCP → каталог → ответ» по [документации MCP](docs/mcp.md).

Цены, сроки, кейсы и показатели на сайте демонстрационные. Заявка сохраняется в PostgreSQL; автоматической рассылки сотрудникам и административной панели в проекте нет.
